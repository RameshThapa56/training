# Skill: Case Study Narrative Structure

Consult when building the case study template or filling in project content. Every case study is a scroll-driven micro-narrative, not a long-form article dump.

## Required narrative beats (in order)

1. **Overview** — project name, client/context, role, timeframe, one-line outcome (the "hook" before anyone scrolls).
2. **Challenge** — the real problem, stated in terms the target audience recognizes (business or user pain, not just "the client wanted a website").
3. **Research / Discovery** — what was learned before designing (optional if not applicable to the project type).
4. **Strategy** — the approach chosen and why, tied back to the challenge.
5. **Process** — key decisions and iterations; show the thinking, not just final screens.
6. **Execution / Solution** — the actual work, richly presented (imagery, video, interactive mockups).
7. **Results** — quantified outcomes where possible (metrics, before/after, client-reported impact). If no hard metrics exist, use qualitative outcome statements — never fabricate numbers.
8. **Client feedback** — a real testimonial tied specifically to this project, if available in `docs/brief.md`.
9. **Next project / related work** — a discovery hook into another case study, keeping the visitor exploring.

## Interaction requirements

- Section-by-section scroll reveals matching this beat order — each section should feel like a chapter, not a continuous wall of text.
- A before/after comparison (slider or side-by-side) wherever the project has a visual transformation.
- Pull-quotes from client feedback surfaced mid-scroll, not only at the end.
- A persistent-but-unobtrusive way back to the full portfolio and forward to the next case study.

## Content rules

- Never invent client names, metrics, or quotes not present in `docs/brief.md`. Where the brief lacks a beat (e.g., no research phase for a given project), omit that section for that project rather than filling with generic filler text — and note the omission in the phase summary.
- Keep each section's copy scannable: short paragraphs, not dense blocks.
